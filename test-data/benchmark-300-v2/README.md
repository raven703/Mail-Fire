# Mail-Fire independent synthetic holdout, 300 EML (v2)

- **Purpose:** evaluate the existing detector and policy stack with realistic Russian-language office email scenarios. **Do not train on these 300 cases.**
- **Files:** `eml/MF300-0001.eml` ... `MF300-0300.eml`; one line per message in `manifest.jsonl`.
- **Generation:** deterministic JavaScript with Node.js >=18: `node scripts/generate_benchmark_300_v2.mjs`. No npm dependencies or external services. MIME attachments: TXT, CSV, HTML, DOCX and XLSX. All EML are checked in.
- **Labels:** `expected_semantic_categories` is author-authored scenario ground truth independent of detector predictions. `annotation_status=synthetic_author_defined` means **not independently expert-reviewed**. Built-in category/rule behavior and actual policy hits may differ; compare separately. `expected_no_issue` describes intended negative semantics, not a guarantee any detector remains silent.
- **Synthetic realism:** Names, employers, procurement terms, contextual threats and credentials are intentionally realistic-looking; identifiers, domains and passwords are invented and are not genuine person/account data. Some identifiers deliberately fail checksum to exercise near misses. Public GitHub repository: do not add genuine confidential documents without explicit secured process.
- **Distribution:** control=60, pii=55, commercial=55, safety=45, secrets=40, documents=25, mixed=20. Exactly 300; multiple semantic labels are allowed for mixed cases.
- **Current scope:** text and parsers for DOCX/XLSX/HTML/CSV/TXT. **OCR images, scanned PDFs, encrypted archives, YARA/ClamAV signatures are NOT tested here**; create distinct fixture packages with controlled binary artifacts. This benchmark does not constitute coverage for those engines.
- **Baseline:** capture deployed Git SHA, enabled detectors, policy exports and OCR/AV/ML settings **before** import. `master` includes report for previous 250 EML but the runtime configuration may differ. Check PR #11 merge status separately.
- **Import:** first pilot 5 EML, then batches of 50. Do not alter production policies, classifier publication, or data retention. Existing messages/incidents must be retained. Use `Message-ID` and benchmark header for provenance. Confirm deduplication and mapping from source EML to DB message ID.
- **Evaluation:** evaluate finding-category precision/recall/F1 incl. unexpected categories; report exact multilabel match, missing/spurious hits, results by difficulty/scenario/attachment, per-attachment extraction failure, PARTIAL causes, and incident policy execution separately. Report absent-positive categories as NOT TESTED. Never claim 100% for an untested feature.
- **Holdout discipline:** do not upload `manifest.jsonl` into ML Training Datasets or fit TF-IDF, SetFit, RuBERT on this benchmark. Treat test labels as independent test keys.
- **Reproducibility:** `node scripts/generate_benchmark_300_v2.mjs /tmp/mf-benchmark-300`, then diff that directory against `test-data/benchmark-300-v2`.
