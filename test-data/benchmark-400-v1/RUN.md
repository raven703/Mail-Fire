# B-400 operational run protocol

1. Freeze input hashes, commit SHA, configuration and rule/policy snapshots. Validate exactly 400 unique MIME messages, 240 attachments, 280 positive/120 controls; inspect ZIP/OOXML/PDF/PNG integrity, native PDF text layer and scan PDF absence of one. Keep manifest outside ingestion. Do not tune rules or labels. If fixtures fail preflight, report and version corrections separately before testing.
2. Use two fresh isolated benchmark DBs with identical configuration (or verified full reanalysis if isolation impossible, report limitation). Run same host and resource limits, concurrency, batch schedule, OCR engine, container images and warm-up method. ML/LLM inference environment gates false; ML, LLM and semantic switches off; OCR enabled. Normalizer A disabled; B enabled, mode detect, sensitivity high. Record effective configuration and verify it remains constant throughout each run. Restore original settings afterward.
3. Adapt benchmark350_live.py into a separate B-400 measurement script for current unified pipeline. Use pipeline.ingestion.accept or actual supported import, normal worker queues, analysis job and final policy evaluation. Validate job ancestry/content snapshot and no cached detections; derive actual current job kinds from source. Use a small pilot, then identical batches (e.g. 50) with fixed submission scheme. Pilot outside measured runs or reset both fresh DBs. No changes to production analysis code, rules or B-350. Do not directly call OCR/detectors for measured run.
4. Record acceptance-to-final latency (mean, median, P95, P99, max), wall time, throughput/hour and extrapolated/day, queue wait vs stage execution, internal analysis timings, CPU/RAM per container at fixed sample interval (mean/peak), host CPU/RAM, queue depth, OOM/retries/errors, final statuses, OCR per attachment/engine and expected OCR/visible text coverage, incident counts and grouping invariant. Record cold/warm state and measurement method. Preserve first-pass failure records, recovery separate.
5. Score all 400, per-message category sets on the 12 RU3 IDs, TP/FP/FN/TN per category, micro/macro F1, exact match, safe-control false alarm rate, cohort and attachment stratification. Treat incomplete runs as incomplete and do not silently drop failures; show separate processing failure counts and successful-only sensitivity if useful. Compare built-in positive probes separately; unannotated built-ins not confirmed FP. Policy hits/incidents descriptive only; no independent policy labels. Compare A/B per-message and list all changed TP/FP/FN with evidence and normalization transformations. Do not optimize between A/B runs.
6. Save separate run dirs test-data/results-benchmark400-YYYYMMDD/{A,B}/ with config, hashes, observations, timing, resources, errors, metrics, attachments and REPORT.md, plus comparison report. Redact secrets from environment/config snapshots. Commit results separately on a results branch; report paths and commit. Do not change prior benchmarks.
