# План реализации

Дата начала: 18 ноября 2026. Репозиторий первоначально пуст.

## Порядок и критерии проверки
1. Инфраструктура: Python 3.12, FastAPI, SQLAlchemy, PostgreSQL/pgvector,
   Alembic, Compose, lock-файлы. Проверка миграций на настоящей БД.
2. Безопасность: Argon2, серверные сессии, RBAC, отдельное право оригиналов,
   аудит, ограничения запросов. API-тесты.
3. Почта: оригиналы и бинарные объекты в БД, события отдельно от содержимого,
   адреса/получатели, EML и extract-msg, файловый импорт со стабильностью файлов,
   безопасный ZIP, статистика импортов, SMTP с доверенными источниками.
4. PostgreSQL очередь: SKIP LOCKED, lease, retries, heartbeat, восстановление,
   быстрые и тяжёлые задания. Проверка аварийных сценариев.
5. Извлечение: MIME, HTML, Office/PDF, ограниченные архивы, статусы ошибок,
   отдельный изолированный процесс обработки. Проверка реальных файлов.
6. OCR: PaddleOCR/RapidOCR, страницы, координаты, confidence, версии,
   повторное использование. Отдельные интеграционные тесты реальных моделей.
7. Детекторы: валидаторы ПДн, секреты, код, injection, опциональные внешние
   анализаторы, корректное отражение недоступности. Unit/security tests.
8. Политики, инциденты, комментарии, назначения, аудит, переанализ.
9. SIEM/outbox с backoff, уведомления, настройки хранения, legal hold, поиск.
10. Эталоны: SHA, фрагменты, MinHash, embeddings/pgvector; контролируемое ML
    с изолированными выборками, метриками и публикацией/откатом.
11. Мониторинг: PostgreSQL, workers, ресурсы, логи, диагностический агент.
12. Русский React/TypeScript интерфейс без фиктивных действий.
13. E2E, security, интеграционные и нагрузочные тесты; эксплуатационная
    документация и точный отчёт о готовности.

## Инварианты
- Не влиять на оригинальную доставку почты; подтверждать SMTP после commit.
- Только PostgreSQL — постоянное прикладное хранилище.
- Message-ID и хеш документа не доказывают общность независимых отправок.
- Не считать ошибку анализатора отсутствием угроз.
- Не исполнять содержимое писем, макросы или инструкции из документов.
- Ни результаты OCR/ML, ни нагрузочные цифры не имитировать.
- Чужих файлов в начальной директории не обнаружено; удаление не требуется.

После каждого блока: запуск целевых тестов, актуализация PROGRESS,
локальный git checkpoint. При исчерпании сессии — CONTINUATION с командами.
