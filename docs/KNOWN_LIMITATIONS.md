# UI/UX — текущий статус

Полная переработка по расширенному ТЗ ещё не завершена. Подробный перечень
открытых функций и непроведённых проверок: UI_UX_DESIGN.md, раздел ограничений.
Проверено 39 backend tests и Chromium smoke, но не все browser E2E,
не 1000+ записей и не нагрузка 60k/day. Per-container health/ресурсы отсутствуют.

# Известные ограничения

Не использовать как промышленную DLP. Реализованная часть проходит ограниченные
автотесты, но не все критерии технического задания.

## Критичные
- Извлечение выполняется в worker с доступом к БД. Read-only Docker filesystem,
  no-new-privileges и cap_drop не заменяют отдельный изолированный parser sandbox.
- SMTP: только IP allowlist, без реализованного AUTH/TLS; TCP-порт опубликован
  на loopback. Без надёжного upstream ID дедупликация SMTP-событий невозможна;
  независимые поступления остаются отдельными событиями.
- Heartbeat/fencing завершения задания есть, fencing публикации всех derived
  результатов ещё нет. Долгая потеря БД может привести к повторной обработке.
- Общий timeout парсеров/ограничение адресного пространства ещё не реализованы.
- Нет rate limiting логина и полного маскирования чувствительных метаданных.

## Функциональные
- Нет работающего OCR, RuBERT/SetFit, Presidio и внешних malware/secret engines.
- ML baseline настоящий: TF-IDF/logistic multilabel, train/validation/test,
  подбор порогов на validation, метрики/gate, публикация и возврат старой версии.
  Однако near-duplicate leakage не устранена: группы защищают только одинаковый
  нормализованный текст. Калибровка, полноценный active learning, сравнение
  моделей, обучение через выделенную очередь и ML UI ещё отсутствуют.
- ML artifacts используют pickle только из доверенной БД. Нет upload артефактов;
  компрометация БД с возможностью подмены artifact ведёт к RCE при загрузке.
- MSG adapter не проверен реальным синтетическим MSG fixture.
- UI ZIP chooser ещё не обновлён; endpoint поддерживает ZIP по содержимому.
- Нет полного SIEM/уведомлений, retention cleanup, эталонов и embeddings.
- Мониторинг пока только базовые счётчики, не полноценная диагностика.
- archive/delete исходников требуют отдельного writable bind mount; Compose
  по умолчанию монтирует источник read-only для leave.
- Начальная миграция использует текущую metadata: перед развитием схемы
  необходимо заменить её неизменяемым историческим DDL.

## Проверки и зависимости
- Нагрузочные 60000 сообщений, OCR/MSG/E2E отказоустойчивость не проверены.
- Npm audit обнаружил 4 high в build-time цепочке Vite. Latest обновление
  их не устранило; force downgrade без анализа не применялся.
- TestClient выдаёт deprecation warning об использовании httpx.

## Уточнение после последнего блока
Некоторые пункты выше теперь частично реализованы: subprocess/seccomp parser,
RapidOCR english image integration, SIEM HTTP/UDP outbox, retention API,
шингловые эталоны и FTS API. Это не закрывает весь соответствующий раздел ТЗ.
Полная контейнерная изоляция без файлового доступа к секретам отсутствует;
OCR ru/Paddle не проверены; SIEM notification email отсутствует; embeddings
отсутствуют; retention auto scheduling отсутствует; новые UI отсутствуют.

## Актуализация изоляции
Предыдущий пункт о запуске парсеров в DB-connected worker устранён в Compose:
parser вынесен в отдельный контейнер без секретов/mounts/DB network. Runtime
проверки доступны в scripts/check_isolation.py. Broker имеет internal network
для входящих запросов API/worker, а subprocess парсера дополнительно seccomp
блокирует все sockets. Защита не является доказательством отсутствия kernel
escape; выделенный runtime вроде gVisor и уменьшенный parser image не внедрены.
Локальный режим без PARSER_URL предназначен только для разработки/тестов.

## Semantic limitations (новый блок)
Embeddings/pgvector теперь действительно реализованы и проверены в Compose.
Порог similarity .8 пока не калиброван на отраслевом датасете; semantic
сходство не доказательство утечки. Reindex API синхронный, максимум 1000
документов каждого типа; массовая фоновая переиндексация ещё отсутствует.
Semantic UI ещё не добавлен. Исходная 0001 всё ещё использует mutable metadata;
0002 — явный неизменяемый DDL. Paddle primary и RuBERT/SetFit не реализованы.
Embedding failure после сохранения original не теряет original, но может
привести к retry/FAILED job; выделенная embedding queue ещё не реализована.
Management: reference reindex и ML train синхронные; переоценка ограничена
1000 последних events, не удаляет прошлые инциденты. Счётчики политик —
созданные инциденты, shadow не имеет отдельного счётчика подавленных сигналов.
Категория reference пока не редактируется; matches показывают сохранённые
инциденты (до 100). Детектор switches управляют policy evaluation, не расходом
CPU инференса. Не добавлены отсутствующие в backend ClamAV/Presidio/Paddle
под видом работающих. Метрики доступны только для реально обученных моделей.
