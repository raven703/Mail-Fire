# RU3 — этапы 2 и 3: проверка оставшихся семи категорий

Baseline: опубликованный RU3 df9f582. Проверены все семь категорий по текущим правилам, manifest и текстам benchmark-350. Правила саботажа сохранены (12 TP, 0 FP, 0 FN в исходном отчёте). Для остальных шести подготовлены изменения. Это статический анализ, не измеренный результат нового matcher.

- Учётные данные: локальные учебные контексты, устранён морфологический дубль, добавлен контекст фактической передачи.
- Фишинг: локальные учебные контексты, более конкретный контекст кода, признаки поддельной формы.
- Вывод информации: отдельное правило конфиденциального архива и внешнего адресата.
- Вымогательство: убрана общая фраза о требовании выкупа, уточнены признаки вымогательства.
- Угрозы: ограниченные локальные исключения для явных художественных цитат и общие признаки угроз. Нельзя считать цитату доказательством безопасности; независимая угроза должна оставаться обнаруженной. Проверить mixed-context cases.
- Саботаж: без изменений; проверить плановые работы и штатное удаление резервных копий.

Итого 41 правил, 245 записей взвешенных терминов, 12 категорий, 8 политик. Существующая команда apply_ru3_pii_calibration теперь охватывает все изменённые категории, атомарно архивирует заменённые строки, сохраняет историю, политики и ручные настройки вне заменяемых категорий. Требуется исходный маркер RU3 df9f582; промежуточные варианты не поддерживаются. Для нового развёртывания используется тот же обновлённый RU3. Не применять до тестов.

Штатный прогон всех 12 категорий:
python scripts/benchmark_ru3_all.py --output /tmp/ru3-all.json

Требуются также Django regression, независимый корпус, отдельная проверка normalizer on/off, проверка команды обновления и сравнение истории. В текущей сессии Django, Razdel, pymorphy3 отсутствуют; штатный прогон не выполнен. Не публиковать прогнозные метрики как фактические. Рабочая БД недоступна через GitHub. После успешной проверки: python manage.py apply_ru3_pii_calibration (preview), python manage.py apply_ru3_pii_calibration --apply --backup-dir /state/dlp-backups (только если каталог действительно persistent). Повторный preview должен показать already_applied. Не сбрасывать каталог через restore.
