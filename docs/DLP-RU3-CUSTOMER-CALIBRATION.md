# RU3 — клиентские и контактные базы

Диагностический replay на 350 замороженных текстах с ручным словарём словоформ (не штатный pymorphy3/Razdel): исходно TP=18 FP=0 FN=2; после изменения TP=20 FP=0 FN=0. Это предварительная оценка на известном корпусе, не независимый holdout.

FN MF350-0326 и MF350-0346: база с чувствительным содержимым без глагола выгрузки. Добавлено отдельное правило: клиентская база (обязательно, вес 5) и конкретный признак содержимого или ограничения (вес 4), порог 9, окно 12, риск 75. Уточнены явные фразы. Убрана общая фраза «выгрузка персональных данных», которая не обязательно означает клиентскую базу. Остальные четыре правила сохранены. Два правила (реестр клиентов и CRM) не дают самостоятельных срабатываний в известном корпусе; сохраняем до проверки независимых сценариев.

Штатная проверка: python scripts/benchmark_ru3_pii.py --category customer --output /tmp/ru3-customer.json. Добавлены 10 регрессионных примеров, штатные Django-тесты и независимый holdout пока не запускались.

Итог пяти категорий: исходно 114 TP / 49 FP / 15 FN; диагностически 129 TP / 0 FP / 0 FN. Эти результаты нельзя переносить на production. Необходимы штатный replay всех 12 категорий, отдельная проверка нормализации, независимый размеченный корпус и тестирование команды обновления.

Ветка объединяет пять калибровок. Команда apply_ru3_pii_calibration применяет их атомарно только с исходного опубликованного RU3 df9f582. Рабочая БД не изменялась. Всего 39 правил / 241 взвешенная запись.
