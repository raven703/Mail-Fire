# Восстановление оригинальной DLP-конфигурации

## Повторяемый запуск

```sh
docker compose exec -T web python manage.py restore_original_dlp
docker compose exec -T web python manage.py restore_original_dlp --check
```

Команда атомарно восстанавливает категории, правила, политики и только настройку
`detectors`. Не импортирует ui-настройки старых пользователей, письма, инциденты,
пользователей или модели. Не удаляет существующие объекты. Дополнительные объекты
перечисляются в `extras`; --check завершается ошибкой при отличиях полей эталонных
объектов, но не при наличии дополнительных объектов. Перед текущим импортом сохранён
локальный backup /home/user/mice-archives/dlp-current-backup.json.

## Источники и границы точности

Эталон test-data/results-benchmark350-20261123/config.json содержит категории,
политики и настройки, но НЕ содержит category_rules или их ID. Правила берутся
без нормализации JSON из config/rulepacks/ru2_morph_weighted_rules.json, поскольку
его 12 category ID точно совпадают с пользовательскими категориями снимка.
Названия, описания и все остальные поля категорий берутся из снимка, а не из RU2.
ID правил — стабильные UUID5 (category ID, индекс и название правила); исторические
ID правил невозможно подтвердить по этим источникам. Политики сохраняют оригинальные
ID, даты, версии, состояния, приоритеты и полный JSON conditions.

base_ru.json содержит другой набор (6 иных категорий, 8 правил) и не добавляется:
его импорт создал бы новые правила, отсутствующие в эталоне. В RU2 нет Regex-правил,
ordered=true, непустых исключений или match_mode=all: эти параметры не выдумываются.
Существующие алгоритмы ANY/ALL, Regex и исключений не изменялись.

## Результат

19 системных категорий совпадали до импорта. Восстановлены 12 пользовательских.
33 keyword-правила: 23 flexible, 7 morphology, 3 word. Regex/reference/ml: 0.
128 взвешенных терминов, из них 37 обязательных. Сохранены индивидуальные веса,
min_score, окна близости, ordered=false и исключения, включая пустые списки.
Настройка детекторов точно восстановлена: {"antivirus": false}.
ML/LLM inference остаются false.

Все поля восстановленных объектов совпадают с выбранными источниками; дубликатов
категорий или правил нет. В БД дополнительно сохранена прежняя политика
MICE smoke: confidential (9f3a1783-341e-40ec-948f-61c057a185ac), связанная с
существующим инцидентом. Таким образом, оригинальных политик 8, всего в БД 9.
Ни письмо, ни инцидент, ни пользователь не удалены: до/после 1/1/1; ML-моделей 0.

## Проверки

- Импорт выполнен дважды, затем --check; расхождений нет.
- 111 Django-тестов прошли в итоговом контейнере, включая 4 новых restoration-теста.
- Положительное срабатывание всех 23 исходных flexible-правил.
- Морфологические формы, недобор веса/отсутствие required, выход за окно,
  ANY/ALL и исключающая фраза проверены точечно; benchmark не запускался.
- Редактор весов: HTTP GET/HX-Request 200 в работающем UI; POST и сохранение
  индивидуального веса проверены в Django-тесте с последующим восстановлением.
- Исправлено сохранение редактора: неизменённые исходные поля не нормализуются,
  порядок фраз не меняется, отсутствующие дефолты не материализуются.
- /api/health возвращает ok.
