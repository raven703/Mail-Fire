# RU3 — калибровка категории пересылки ПДн (этап 1, категория 1)

Источники: RU3 df9f582, frozen observations и manifest benchmark-350, отчёт DLP-RU3-BENCHMARK. Не сравниваем с RU2.

Диагностика: 14 отрицательных для категории писем MF300-0061, 0065, 0069, 0073, 0077, 0081, 0085, 0089, 0093, 0097, 0101, 0105, 0109, 0113 содержат «копия паспорта сотрудника» в разных словоформах. Это сценарии passport_russian, не доказательство передачи ПДн. Удалены две фразы простого упоминания копий паспортов; слово «копия» больше не заменяет глагол передачи скана. Структурный паспортный детектор не менялся.

Четыре пропуска MF350-0315/0318/0320/0350 относятся к альтернативным обозначениям личных/персональных сведений и закрытым реестрам. Добавлены два контекстных правила (обязательная двухсловная фраза 6 + действие 4, порог 10, окно 12), уточнены явные обозначения выгрузок/закрытых списков. Старое правило «Переслать персональные данные» сохранено.

Предварительный диагностический replay 350 записей с ограниченным ручным словарём словоформ (не pymorphy3, не Razdel) воспроизвёл 18 TP / 14 FP / 4 FN; после изменения 22 TP / 0 FP / 0 FN. Это результат приближённого сопоставления на уже известном корпусе, не подтверждённый результат production matcher и не независимая оценка. Добавлены синтетические regression cases; независимый holdout ещё нужен. Не использовать 100% как production accuracy.

Проверка штатным matcher: `python scripts/benchmark_ru3_pii.py --output /tmp/ru3-pii.json`. Запустить `python manage.py test policy_engine.test_ru3_pii_calibration policy_engine.test_ru3` в установленном окружении. Эти команды в текущей сессии не запускались: pymorphy3/Razdel отсутствуют, установка недоступна. Перед применением проверить полный регрессионный прогон и новый контрольный корпус. Негативные формулировки и цитаты остаются отдельной задачей; не добавлены широкие исключения, которые могли бы скрывать истинную передачу.

После подтверждения результатов: `python manage.py apply_ru3_pii_calibration` (preview), затем `python manage.py apply_ru3_pii_calibration --apply --backup-dir /durable/backup/path`. Команда обновляет только эту категорию: сохраняет первый rule ID, архивирует два изменённых правила и создаёт четыре новых. Сохраняет историю, политики и настройки. При расхождении локальной конфигурации останавливается. Новые установки получают обновлённый RU3 (38 правил, 239 взвешенных записей). Не применять общий restore/import поверх установленного RU3.

Другие 11 категорий и политики, OCR, ML/LLM не менялись.
